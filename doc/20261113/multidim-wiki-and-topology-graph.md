# 多维 Wiki 与异构拓扑图谱落地记录

## 背景与目标

真实个人备忘往往同时跨越多个正交维度（例如一条公开课收藏在“主题域”属于学习、在“载体形态”属于网站、在“时间”上关联某周日程）。如果仅靠目录层级或单一主题页归类，不仅难以兼顾多视角检索，也无法长出清晰的知识拓扑。本次迭代在不引入外部图数据库、坚持 Markdown 文件为唯一真相源的前提下，补齐正交多维分类、事件日期索引、有类型关系边与拓扑图谱导出能力。

## 方案与架构要点

1. **Markdown 单一真相源，全库纯派生**：
   - 页面头部支持节点类型（主题、实体、人物、项目、资源、事件）与页面公共维度；列表条目支持行内维度补充与公历事件日期标记；跨页链接支持明确的关系语义（属于、组成部分、使用、替代、涉及、一般关联）。
   - 数据库新增的页面节点表、页面维度表、原话维度表与事件日期表全部由索引同步流程从工作区文件一键确定性生成，不触碰原始消息事实表的只追加约束，工作区版本快照即可完整还原图谱与索引。
2. **受控词表防标签发散**：
   - 全局配置定义固定维度键（主题域、载体形态、状态、细分话题）与推荐值，允许在用户工作区缓存中渐进沉淀个人高频词；全局重整阶段自动提示合并孤立近义标签。
3. **切片级第四路召回与日期硬筛**：
   - 检索路由结合当前日期（含星期）与受控词表，自动抽取正交维度与时间区间；第四路直接在小节切片粒度上做维度匹配，并在日期窗口内存在相应命中时执行日期硬筛（同时保留近期未归档原话进语义重排兜底；若高分词法或维度命中全部落在日期窗口之外，则不误删正解，自动回退保留并提示核对日期）。
   - 一跳邻域边按归属、组成、替代、使用、涉及、一般关联与出边优先的确定性顺序去重，消除随机邻居抖动。
4. **PostgreSQL 原生异构拓扑组装**：
   - 将主题页节点、虚拟维度枢纽节点、原话节点与有向类型边统一输出为标准图结构，支持多维交集筛选与 1~3 跳邻域下钻，前端可直接接入图谱渲染库，省去独立图数据库的资源与同步负担。

## 验收结论（2026-11-13）

- **数据库迁移与安全隔离**：`003` 迁移已在独立业务库执行完毕（含切片级 `wiki_chunks.facets` 与 GIN 索引），新增四张派生表全部启用强制行级安全（`ENABLE + FORCE RLS`），无租户上下文或跨租户查询均返回 0 行；`sync_wiki` 同步写入显式携带 `user_id` 条件。
- **离线与组件测试**：31/31 全部通过（静态检查 `ruff` 零告警），覆盖旧格式无感兼容、多维与日期区间解析、`[inferred]` 推理行内标签防污染、切片级维度隔离、日期硬筛与 `pending` 兜底、邻域确定性去重、已晋升热区词条防重整空转及多租户隔离。
- **真机端到端验收**：修复前 5 大场景 27/27 断言全部通过。同一条课程网站备忘经夜间整理自动生成多维标签、换算出公历事件日期并建立跨页 `uses` 类型链接；随后分别从“学习类课程资料”和“收藏过的网站”两个正交维度提问均精准命中原话，拓扑接口验证同一页面节点同时挂接两个维度枢纽。测试租户数据已自动清理。
