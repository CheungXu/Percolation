# Agent 可观测性与轨迹仓落地记录

## 背景与目标

此前每次运行只留一份简短事件流（工具结果只截前 300 字，没有完整提示词和思考过程），出了问题难以复盘，也算不清花了多少钱。本次目标：

1. 完整提示词、模型思考过程、工具返回的超长原文全部记录，默认开启全量录制。
2. 轨迹保存在 NAS 上，但与用户数据严格隔离。
3. 补齐追踪、成本、版本管理和防失控能力，并有可视化面板。

## 方案决策

| 议题 | 决定 | 理由 |
| --- | --- | --- |
| 真相源放哪 | 自建 NAS 轨迹仓 | 数据完全自主；平台可替换、可重放；不受第三方保留期限制 |
| 可视化 | 本机 Arize Phoenix 单容器 | 调研的四个开源方案中资源占用最小（实测约 460MB），原生支持 OpenTelemetry 标准 |
| Phoenix 自身数据 | 共享数据库实例上的独立库与独立账号 | 不用 SQLite 放 NAS（锁不可靠）；与业务库、业务账号完全隔离；不需要重启实例 |
| 录制粒度 | 默认全量，可切换为摘要 | 满足复盘需求，同时保留降级开关 |
| 治理能力放哪 | 放在自研内核里 | 预算、防死循环、成本核算不依赖任何平台，换平台不丢 |

## 交付内容

- **轨迹仓**：NAS 上与用户数据目录平级的独立目录，仅运维账号可访问，不挂进任何智能体沙箱。每次检索、每次整理各生成一条压缩轨迹，附月度索引；提示词等重复内容只存一份。落盘前自动抹掉密钥。
- **全量录制**：每个智能体的完整消息数组、每次模型调用的回复与思考过程、每次工具调用的未截断原文、召回的文档，以及每一步的耗时与用量。
- **成本账本**：按百炼刊例价把每次调用折算成人民币，能按运行类型、按天、按模型、按智能体版本汇总。
- **版本指纹**：提示词、工具或模型参数一改，指纹随之变化，效果与成本可以按版本对比。
- **防失控**：单次运行预算上限（默认 5 元 / 300 万 token），同一调用连续重复超过 2 次自动拦截。
- **可视化面板**：本机 Phoenix 实时接收同一份轨迹，可逐层展开调用树查看提示词、思考、工具原文；仅本机回环地址可访问，开启登录认证。
- **查询工具**：命令行列表、调用树展示、完整还原、统计汇总、任意 SQL 查询、历史轨迹回放到面板。

## 验收结果（2026-11-13）

- 单元测试 22/22 通过（新增 7 项覆盖轨迹、成本、护栏、落盘与导出）。
- 真机端到端 21/21 通过。首轮回归 18/21：借助新轨迹的思考过程，十分钟内定位到“作答节点凭品牌联想猜测暗语”的提示词缺陷，修正后全部通过。
- 面板实收 18 条轨迹、329 个节点，五类节点均被正确识别；未带凭据的推送被拒绝（401）。
- 实测成本：一次检索约 0.002~0.014 元，一次整理约 0.12~0.28 元；一次完整端到端验收约 0.5 元。
- 实测存储：一次检索 3~7KB、一次整理 7~12KB。

## 资源与安全

- Phoenix 常驻内存约 460MB（上限 1GB），仅监听本机；远程查看需 SSH 端口转发。
- 新增数据库对象仅限独立库 `percolation_obs` 与同名普通账号（无超级权限、不能绕过行级安全），未改动业务库与实例参数。
- 所有凭据只存于 `config/` 下权限 600 的配置文件，不进版本库。

## 后续建议

1. 用户注销时同步清理其轨迹（按租户删除轨迹文件与索引行，再回收无引用的共享内容）。
2. 设定轨迹保留期限（面板侧已设 90 天，NAS 侧待定）。
3. 从轨迹中挑选典型问答沉淀为评测集，提示词改版前先跑回归。
4. 多机部署时把索引改为按进程分片，避免并发追加同一文件。
5. 夜间整理任务上线后，按日统计成本与失败率，超阈值告警。
