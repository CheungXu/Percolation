# Percolation 可复用智能体底座与检索/整理双引擎交付总结

## 1. 本阶段核心成果

继存储底座（广州通用型 NAS）与多租户隔离数据库（广州 RDS PostgreSQL 独立库）就绪后，项目已完成**阶段二（轻量智能体内核与录入/检索闭环）**与**阶段三（后台离线整理与热度置换引擎）**的全部研发与真机闭环验收：

1. **沉淀通用智能体内核（`agentkit`）**：将模型通道调度、工具调用循环、输出结构校验、按需技能加载、受限目录沙箱以及多租户事务隔离抽离为完全独立于具体业务的底层模块。后续团队孵化其他智能体应用时，可直接复用该内核，仅需编写业务规则与提示词即可快速上线。
2. **打通在线四步混合检索（`Search Agent`）**：实现“个人高频背景预加载 → 主题库与近期未归档原话双轨并查 → 候选缓存区静默翻查兜底 → 最小化追问与澄清固化”的完整体验。刚随手发出的碎片无需等待夜间整理即可秒级查到；生僻暗语优先由后台静默翻查历史档案化解，不轻易打扰用户。
3. **打通夜间自底向上整理（`Dreaming Agent`）**：实现按活跃变更唤醒、单用户防并发重入、上下文连发拼图归档、冷热记忆自动升降级以及版本快照保护。当某条低频暗语在两周内连续帮上忙两次以上时，系统会在夜间自动将其晋升至高频热区，后续同类提问响应时间直接缩短一半以上。

## 2. 业务工作流概览

### 2.1 日常录入与提问流程

1. **随手记**：用户输入任意零碎短句或半截话，系统毫秒级原样存档，3 分钟内的连续输入自动归为同一事件批次，不打断用户。
2. **模糊问**：
   - **第一步（读常用背景）**：结合常驻热区记忆理解指代，扩展出多组搜索词。
   - **第二步（双轨查找与原话核对）**：同时搜索“已整理的主题页”和“刚记下还没整理的最新原话”，核对原始记录后直接给出带时间限定的准确回答（实测约 7～9 秒）。
   - **第三步（静默翻查冷门档案）**：若遇到不常见的个人称呼或旧代号导致首轮没查到，系统先不追问用户，自动在安全隔离沙箱内翻查候选档案库；一旦找到对应解释，自动换词重查并给出答案（实测约 16～23 秒），同时记下这次命中。
   - **第四步（极简追问闭环）**：只有翻遍候选档案仍无法区分或确无记录时，才向用户简短追问一句；用户的回答会被标记为高优先级事实永久记住，同类暗语不再问第二次。

### 2.2 夜间自动整理与冷热进化流程

每晚低峰时段（预设凌晨 03:30，目前保留手动触发，随时可开启定时），系统仅挑选白天有新记录或翻查过候选档案的用户自动执行整理：

1. **还原语境归入主题页**：把白天的零碎原话按连发批次拼合，归入长期主题页，严格区分“用户明确说的事实”与“系统上下文推测”，每条结论均绑定原话编号防失真。
2. **冷热自动升降级**：将近期频繁被用到的确认暗语自动提升进常驻热区（提速后续提问）；当常驻热区接近篇幅上限或满一周周期时，自动把长期未用的冷门条目下沉回候选档案库，并合并重复主题页。
3. **安全兜底与一键回退**：每次整理自动保存版本快照；若中途遇到网络波动或异常，自动退回整理前状态，原话完好保留至下次重试。
