# 可复用的轻量 Agent 内核：怎么拆、拆到哪一层

本文总结在 Percolation 里落地 Search Agent 和 Dreaming Agent 时抽出来的通用内核（`code/agentkit/`），以及真机跑下来的经验。目标是以后再建 agent 时，只写配置、工具和编排。

## 一、拆分边界

一个 agent 由四样东西组成，前三样每个项目都一样，只有第四样是业务：

1. **循环**：调模型、执行工具、回灌、校验输出。语义固定，200 行以内。
2. **资源**：模型客户端、沙箱、工作区、数据库租户上下文、追踪。全部放进一个 `RunContext`，工具只能从这里拿资源。
3. **约束**：工具的参数 Schema、输出 Schema、写入校验钩子、轮数上限。
4. **业务**：工具的具体实现、提示词、多步编排。

判断一段代码该不该进内核，看它是否出现任何业务名词（表名、目录名、提示词内容）。出现了就留在业务层。

## 二、编排用普通代码，模型只做判断

不要把多步流程写进一个大提示词让模型自己走。Percolation 的检索是四步状态机，整理是五步流水线，每一步是否执行、失败后去哪，都由 Python 决定。模型只出现在“需要理解语言”的节点上，每个节点是一个独立的 `AgentSpec`，有自己的工具集和输出模型。

好处：

- 每个节点的权限可以收到最小。例如候选区探查节点只能看到 `MEMORY_CACHE/`，沙箱里也只挂载这一个目录；归档节点不能写热区 `MEMORY.md`，只有升降级节点能写。
- 每个节点的输出是强类型的，下一步可以写确定性判断（例如 `status != "answered"` 才进兜底）。
- 出问题时能从追踪里精确定位到哪个节点、第几轮、哪次工具调用。

## 三、内核里值得固定下来的设计

- **模型按槽位取**：业务只写 `router_model`、`dream_model`，具体模型在 `models.json` 里换。
- **一律流式请求**：部分厂商开启思考时不接受非流式；流式下 `tool_calls` 是分片的，要按 `index` 拼回。
- **工具异常不崩循环**：参数校验失败、工具报错、调用不存在的工具，全部变成 `ERROR: …` 文本回灌给模型。
- **输出校验加一次修复**：解析失败时把错误回灌、撤掉工具再要一次。容忍 Markdown 代码块包裹。
- **轮数用完强制收敛**：追加一句“轮数已用完”，撤掉工具，逼模型基于已有信息作答，而不是抛异常。
- **系统提示词固定，动态内容放输入**：输出 Schema 和技能索引也拼在系统提示词里，保证前缀稳定。实测百炼上同一节点重复调用时，缓存命中约占输入的一半到三分之二。
- **技能按需加载**：提示词里只放“名称：一句话简介”，正文由模型调 `read_skill` 读取。
- **文件工具是工厂**：`workspace_tools(scope=…, writable=…, write_prefixes=…, validators=…)`，同一套代码生成不同节点的不同权限。shell 一律进只读沙箱，写文件只走 Python 写工具（便于校验）。
- **测试替身**：`ScriptedChatClient` 按顺序回放预设响应，循环的各种分支都能离线单测。

## 四、真机跑出来的经验

1. **模型报告的标识符要在代码里归一**。候选区命中由模型报告文件名，同一个文件两次分别写成 `MEMORY_CACHE/slang.md` 和 `slang.md`，按文件名分组统计时被拆成两条各 1 次，晋升阈值 2 次永远达不到。凡是要拿来做统计、去重、比对的字段，都在入库前归一，统计时再按语义键（条目键）分组。
2. **预取证据后要明确告诉模型“够了就直接答”**。作答节点的输入里已经附了检索结果和原话，但第一版几乎每次都把 5 轮工具额度用满（在 wiki 目录里 `ls`、`rg`），一次带兜底的检索要 15 次模型调用、近 30 秒。删掉作答节点用不上的 `list_dir`/`bash`，轮数降到 3，并在提示词里写明“多数情况足够回答，这时不要调用工具”。
3. **不要只信模型的完成报告，用文件对账**。整理节点汇报“已归档的序号”，代码再扫一遍文件里实际出现的 `#msg_N` 锚点取并集；两边都没有的保持待整理，下次重试。
4. **失败要能整体回滚**。工作区是 git 仓库：成功就提交，失败就 `reset --hard` + `clean`，再按文件重建数据库索引，保证“文件即本体、库即索引”始终一致。
5. **会话级咨询锁要绑一条专用连接**。`pg_try_advisory_lock` 是会话级的，用连接池时必须在同一条连接上加锁和解锁，运行期间不归还。
6. **事务要短**。数据库设了 `idle_in_transaction_session_timeout = 60s`，所有模型调用都在事务外，事务里只做读写。

## 五、新建一个 agent 的清单

1. 确认需要哪些槽位，必要时在 `models.json` 加模型。
2. 写业务工具：pydantic 参数模型 + 从 `ctx.deps` 取依赖的处理函数。
3. 每个需要模型判断的节点写一个 `AgentSpec`：固定提示词、最小工具集、输出模型、轮数。
4. 用普通 Python 把节点串成流程，所有确定性判断留在代码里。
5. 用 `ScriptedChatClient` 写分支单测；再写一个真机端到端脚本，用独立测试租户跑完就清理。
