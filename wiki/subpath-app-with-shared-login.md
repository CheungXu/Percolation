# 在已有站点的子路径挂新产品，并复用主站登录

适用场景：已有一个带账号体系的站点（这里是星页 `stars-page.com`），要上线一个独立的新产品（拾记凝境），希望用户直接用原账号登录，但两个项目的代码、数据库、发布节奏互不耦合。

做法一句话：**新产品挂在主站同域的子路径下，浏览器自然带上主站的登录 cookie；新产品后端把 cookie 原样转给主站的「我是谁」接口换出账号，再按账号 id 自动开自己的租户。**

参考实现：`code/percolation/api.py`、`code/percolation/product/identity.py`、`config/nginx/percolation.conf`、迁移 `code/db/migrations/005_product_web.sql`。

---

## 一、为什么选同域子路径

| 方案 | 问题 |
| --- | --- |
| 子域名（`app.example.com`） | 主站 cookie 默认只属于主域，要改成 `Domain=.example.com`，影响主站全部会话；还要新证书 / 解析 |
| 独立账号体系 | 用户要再注册一次；短信、协议、风控都要重做 |
| 新产品直连主站数据库校验会话 | 耦合主站表结构和签名密钥，主站一改就坏 |
| **同域子路径 + 转发 `/me`** | 主站零改动（只加一行 Nginx include）；新产品只依赖主站一个稳定接口 |

前提：主站登录 cookie 的 `Path=/`（星页是 `sp_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`）。

## 二、组成部分

1. **Nginx 片段放在新项目仓库里**，主站配置只加一行 `include`，写在主站兜底 `location /` 之前的同一个 server 里：

   ```nginx
   location = /Percolation { return 301 /Percolation/; }
   location ^~ /Percolation/ {
       proxy_pass http://127.0.0.1:8710/;   # 末尾斜杠：转发时去掉 /Percolation 前缀
       proxy_read_timeout 180s;
   }
   ```

   - `proxy_pass` 带末尾 `/` 才会去前缀；新产品后端因此按根路径提供页面和接口，本机调试和线上用同一份代码。
   - 不带斜杠的 `/Percolation` 必须 301 到带斜杠的地址，否则页面里的相对路径会解析到站点根目录。路径区分大小写，常见的小写写法也顺手跳转。
   - `^~` 防止主站以后加的正则 location 抢走匹配。
2. **网页里全部用相对路径**（`v1/notes`、`app.js?v=…`）；只有调主站接口（登录、退出）用绝对路径 `/api/auth/...`，同域直达主站。
3. **身份识别**：后端读 cookie，带上它请求主站的 `/api/auth/me`（走本机内网入口，不绕公网），拿到账号 id。
   - 结果在进程内按 cookie 的哈希缓存（登录 60 秒、未登录 5 秒），避免每个请求都打主站。
   - 主站返回 401/403 视为未登录；连不上或 5xx 要单独报 503，前端提示「稍后再试」，不能弹登录框误导用户。
   - 退出登录时，前端先调新产品的「清缓存」接口（此时 cookie 还在），再调主站的退出接口。
4. **租户开户**：账号 id 映射成租户标识（`sp-<uuid>`），首次访问时开户。运行时数据库账号不给 `users` 表的 INSERT 权限，开户只走一个 `SECURITY DEFINER` 函数，函数里用正则限定只接受外部账号格式，防止被用来建内部租户。
5. **登录界面放在新产品里**：直接调主站同域的发验证码 / 登录接口，传主站要求的协议版本（写进配置，与主站前端常量保持一致），协议链接指向主站页面。用户全程不离开新产品。
6. **公网模式关掉调试入口**：本机调试用请求头指定租户很方便，但线上必须忽略这个头（否则任何人都能冒充）；接口文档、手动触发高成本任务的接口一并关闭。用一个配置开关区分两种模式，默认值取安全的那一个。

## 三、验证方法

- 未带 cookie、伪造 cookie、带调试请求头三种情况都应返回 401。
- 真实登录路径需要一个有效会话。可以给主站的测试账号临时签一个会话（用主站自己的服务代码），跑完冒烟测试立刻吊销，并删掉它在新产品里产生的租户数据。
- 浏览器走查用两种模式各跑一遍：本机调试模式跑完整业务流程，线上模式只检查登录卡和已登录冒烟。

## 四、踩坑

- **手工删租户后要重启新产品服务**：进程里缓存了「账号 → 租户 id」的映射，正常运行中租户不会被删，所以没做失效逻辑。
- **主站配置文件归主站仓库管**：改服务器上的配置后，要把同样的 include 行写回主站仓库的副本，并在主站的 Nginx 说明里注明这些片段来自哪个项目，否则下次主站同步配置会把它冲掉。
- **主站会话 cookie 若带 `Secure`**，只有 HTTPS 访问能拿到；IP 直连的 HTTP 地址上新产品永远是未登录状态，不要在那里验收登录。
- **`pkill -f <串>` 会匹配到执行它的 shell 自己**（命令行里含同样的串），停调试进程改用端口查 PID：`ss -ltnp | grep :8711`。
