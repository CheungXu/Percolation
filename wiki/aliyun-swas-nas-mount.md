# 轻量应用服务器挂载阿里云通用型 NAS

适用场景：计算节点是阿里云轻量应用服务器（控制台在「轻量应用服务器」，不在云服务器 ECS 实例列表），需要在同地域挂载通用型 NAS，让多台机器或后续沙箱共享同一份 POSIX 目录。

## 先认机器

轻量应用服务器和云服务器 ECS 是两套控制台。ECS 实例列表为空，不代表这台机器不在当前账号。用公网地址、内网地址和主机名到轻量应用服务器控制台核对。

实例元数据里的 `vpc-id` 是阿里云托管的发起端专有网络，用户在专有网络控制台里看不到它。广州这台机器的网段是 `172.16.0.0/12`，内网地址落在 `172.19.0.0/18`。

## 网段不能重叠

账号里的默认专有网络经常也是 `172.16.0.0/12`。内网互通可以显示「已激活」，但两段完全重叠，发往 NAS 挂载点的包没有可用路由。

做法：

1. 新建一块专有网络，网段用和 `172.16.0.0/12` 不重叠的私网，例如 `10.0.0.0/16`。
2. 在 NAS 购买页实际提供的可用区里建交换机。2026-11 广州容量型通用 NAS 的购买页只提供可用区 A，交换机就建在可用区 A。通用型 NAS 允许跨可用区挂载，轻量服务器在可用区 B 也可以挂。
3. 文件系统和挂载点都放在这块新网络里。协议用 NFS，权限组用「VPC 默认权限组（全部允许）」，对等连接过来的客户端地址才能访问。
4. 在轻量应用服务器「内网互通」里把新专有网络加为接收端。同一地域第一次开通会让该地域全部轻量服务器停机大约 1 分钟；已经有对等连接时再加一条，不会再次停机。

容量型按实际用量计费，空文件系统费用接近 0。个人记忆、配置和知识库这种小文件、低吞吐场景用容量型即可。回收站可以开，保留时间宜短。生命周期沉降和云备份会改变读延迟或在试用期结束后计费，默认先不开。

## 怎么判断已经通

NAS 挂载点通常不回应 ping。域名能解析到挂载点内网地址，并且 TCP `2049`（以及 NFSv3 需要的 `111`）能连上，才说明对等连接已经可用。

通用型 NAS 的挂载域名形如 `{文件系统ID}-{后缀}.{地域}.nas.aliyuncs.com`。在阿里云内网 DNS 下它会解析到挂载点的私网地址。

Linux 挂载使用 NFSv4，并带上 `noresvport`，避免 NFS 会话卡在失效连接上：

```bash
mount -t nfs -o vers=4.0,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport \
  <挂载域名>:/ /mnt/<目录>
```

开机自动挂载写进 `/etc/fstab`，选项加上 `_netdev,nofail`，这样网络未就绪或 NAS 短暂不可用时不会把机器卡在启动阶段。

## 本次已落地的实例

Percolation 使用的就是这套做法，资源在广州：

| 项 | 取值 |
| --- | --- |
| 文件系统 | `2822djfavfuk6w1024j` |
| 挂载域名 | `2822djfavfuk6w1024j-sgw41.cn-guangzhou.nas.aliyuncs.com` |
| 挂载点地址 | `10.0.0.97` |
| 专有网络 | `vpc-7xvpcy2yvh80uagodkeia`（`percolation`，`10.0.0.0/16`） |
| 交换机 | `vsw-7xvsdys836b07v8nfsobu`（可用区 A，`10.0.0.0/24`） |
| 对等连接 | `vpcCon-547ea7e17f914bf4bfd9b11935b11b22` |
| 本机目录 | `/mnt/percolation` |

同一账号里还有一条接到默认专有网络 `vpc-7xvp2f4ul61d5t165jduc` 的对等连接。那条网络与轻量服务器网段重叠，不要把新的 NAS 挂载点放到那里。
